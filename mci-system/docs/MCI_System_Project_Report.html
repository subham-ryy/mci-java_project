1. Plain-English Overview (For Beginners)

1.1 What is the MCI System?

Imagine you are the manager of a company. A client walks in and says: "Research the latest news on artificial intelligence and give me a summary report." As the manager, you don't do all the work yourself in a panic. Instead, you follow a structured process:

  1. You break the big job into smaller steps: Step 1 (Search data), Step 2 (Analyze), Step 3 (Write document).
  2. You assign each step to a specialist: The researcher gathers data; the technical writer formats the report.
  3. You have a security guard at the door: No employee can access files or write to the file cabinet without permission and without signing an audit register.
  4. You log everything in a ledger book: Every task, status, file created, and security decision is recorded so you can inspect it anytime.

The MCI System is exactly that office, implemented entirely in Java code!

The Real-World Analogy at a Glance
  • User: The client who gives a high-level objective (e.g., "Analyze AI trends").
  • Planner / Orchestrator: The team lead that divides the objective into sequential subtasks.
  • Agents: The team members (specialized in data analysis, reports, etc.) powered by Google Gemini AI.
  • Tool Gateway: The security checkpoint ensuring agents only touch files they are allowed to touch.
  • SQLite Database: The persistent company ledger that stores all runs, subtasks, and audit logs.

1.2 Why is this Needed? (The Problem with Normal AI Prompts)

When beginners use ChatGPT or Gemini directly in a single web prompt, the AI frequently hallucinates, cannot reliably execute multi-step computer tasks, and has no safety guardrails. If you gave an AI unrestricted access to your computer, it could accidentally delete system files or leak private data.

The MCI System solves this by providing:

  • Deterministic Structure: Every action is broken down into structured, trackable steps stored in a database.
  • Total Governance & Safety: Agents never touch files directly. They must submit a ToolRequest to the ToolGateway, which checks permissions and logs the attempt before anything is touched.
  • Resilience: If an AI service experiences network congestion or rate limits, the system catches the error, falls back gracefully, and skips dependent subtasks cleanly.

2. Core Concepts Explained Simply

2.1 What is an "Agent"?

In everyday tech buzzwords, "AI Agent" sounds mystical. In our Java codebase, an agent is just an implementation of a simple Java interface: 

public interface Agent {
    AgentResult execute(SubTask subTask);
}

When an agent runs:

  1. It reads what it is supposed to do from subTask.description().
  2. It creates an AI prompt and sends it to Google's Gemini LLM.
  3. It inspects the result: if it needs to save a report or read a file, it asks the ToolGateway.
  4. It returns an AgentResult.success(...) or AgentResult.failure(...).

2.2 What is the "Tool Gateway"? (Our Key Security Feature)

The ToolGateway is the security boundary of our entire architecture. It enforces the Principle of Least Privilege.

Security Gateway Execution Pipeline

Whenever an agent wants to do an action (e.g., write a file), it cannot do new FileWriter(...). Instead, it must call gateway.execute(request). The gateway executes three strict steps:

  1. Permission Check: Does PermissionPolicy allow this AgentType to run this tool? (e.g., REPORT agent can file.write, but unauthorized agents are blocked).
  2. Pre-Execution Audit Logging: The decision (ALLOW or DENY) is recorded in SQLite BEFORE the tool runs. Even if the program crashes or the tool fails, the audit trail is preserved!
  3. Safe Execution: Only if allowed, the tool is called within a sandboxed directory (./workspace/) with canonical path verification to prevent path-traversal attacks.

2.3 What is "LangChain4j"?

You know how Java uses JDBC to connect to databases? With JDBC, you use standard classes like Connection, Statement, and ResultSet whether your database is MySQL, PostgreSQL, or SQLite.

LangChain4j is the "JDBC of Artificial Intelligence". It is a clean Java library that provides standard interfaces like ChatLanguageModel. Whether we talk to Google Gemini, OpenAI ChatGPT, or a local Ollama model, our agent code stays identical. In our project, all Gemini interactions are isolated inside a single beginner-friendly class: LlmFactory.java.

2.4 What is SQLite & Why Did We Choose It?

SQLite is a self-contained, serverless SQL database engine. Unlike MySQL or PostgreSQL, you do not need to install a database server, configure user passwords, or run background daemons. The entire database is stored in a single file: ./data/mci.db.

This makes our project 100% portable: any classmate or teacher can clone our repository and run it immediately with zero database setup.

3. Technical Architecture & Module Deep-Dive

3.1 Maven Multi-Module Structure

Our project is structured as a professional Maven multi-module system. This enforces strict separation of concerns — classes in one module cannot accidentally violate architectural rules of another.

Module Role & Purpose Key Classes
mci-core Domain records, enums, and data models. Zero external dependencies. Task, SubTask, AgentType, TaskStatus, ToolRequest, ToolResponse, Decision
mci-persistence SQLite database connection and JDBC Data Access Objects (DAOs). Database, RunDao, SubTaskDao, ArtifactDao, AuditDao, schema.sql
mci-tools Safe implementations of computer tools (file read/write, path checking). Tool interface, FileTool
mci-gateway Security policy enforcement and audit recording. ToolGateway, PermissionPolicy
mci-agents LLM connection factory and agent execution logic. LlmFactory, Agent, SimpleAgent
mci-orchestrator Goal decomposition (Planner) and task dependency execution (Scheduler). Planner, Scheduler
mci-app Interactive Command-Line Interface (CLI), environment loader, and main runner. Main, EnvLoader

3.3 Database Schema (SQLite Relational Design)

The system automatically creates 4 tables on first launch:

  • runs: High-level objectives submitted by the user (with status PENDING, RUNNING, DONE, or FAILED).
  • subtasks: The breakdown created by the planner, including foreign key run_id, assigned agent_type, dependencies, and final result text.
  • artifacts: Metadata for files generated during the run (e.g., report.md) including file paths and MIME types.
  • audit_log: Security ledger recording every single tool invocation, agent identity, timestamp, decision (ALLOW/DENY), and reason.

5.2 Common Questions Teacher Might Ask (With Recommended Answers)

Q1: Why did you split the project into so many Maven modules instead of one folder?
Answer: "Separation of concerns. In software engineering, modularity prevents tight coupling. For example, mci-core has zero dependencies, meaning our data models are pure. mci-gateway does not know about specific agents, only tools and policies. This architecture allows multiple developers to work on different modules in parallel without code conflicts."
Q2: What is the purpose of the ToolGateway? Why not let agents use FileWriter directly?
Answer: "Direct access is dangerous. In autonomous systems, allowing an LLM unmonitored file access violates the principle of least privilege. The ToolGateway acts as a security firewall: it verifies agent permissions, records an immutable audit log entry in the database BEFORE the operation happens, and ensures file paths cannot escape the sandbox using canonical path validation."
Q3: What happens if Google's Gemini API is down, rate-limited, or slow?
Answer: "Our system is fault-tolerant. In Planner.java, we wrap the Gemini API call in a try-catch block. If an HTTP 503 or network failure occurs, the planner automatically falls back to a deterministic 3-step plan. In Scheduler.java, if a subtask fails, all downstream subtasks that depend on it are safely marked as SKIPPED."
Q4: Why did you use SQLite and standard JDBC rather than JPA/Hibernate?
Answer: "For college evaluation and simplicity, standard JDBC with SQLite is zero-configuration and transparent. There is no heavy ORM overhead, no complex mapping XMLs, and anyone can inspect the exact SQL queries in our DAO classes. The database file mci.db can be opened and verified with any standard SQLite viewer."
Q5: What is LangChain4j and why did you use it?
Answer: "LangChain4j is the leading Java framework for AI integration. It acts like JDBC for LLMs. Instead of manually writing HTTP client requests and JSON parsers for Google Gemini, LangChain4j gives us a clean ChatLanguageModel interface. If tomorrow we want to switch from Gemini to local Ollama or OpenAI, we only change one line in LlmFactory.java."
