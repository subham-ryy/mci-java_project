SECTION 1: OPENING HOOK & ELEVATOR PITCH (1 Minute)
================================================================================

[WHAT TO SAY TO MAM]:
"Good morning Mam. Today I am presenting my project: the Multi-Agent Cognitive 
Intelligence System, or MCI.

In traditional AI applications, a single LLM tries to do everything—answering 
questions, writing code, browsing the web, and compiling documents all in one 
turn. This leads to hallucinations, lack of verification, and huge security risks 
when LLMs are given access to operating system commands.

MCI solves this by implementing an enterprise-grade Autonomous Multi-Agent 
Platform in Java 21 and Spring Boot, powered by live Google Gemini AI. Instead 
of a monolithic prompt, MCI uses specialized autonomous agents:
  1. A Planner Agent that decomposes high-level goals into a Directed Acyclic Graph (DAG).
  2. A Navigator Agent that browses external web sources and extracts live data.
  3. A Docker Agent that writes Python code, runs it in an isolated container sandbox,
     and autonomously debugs itself if there is an error.
  4. A Data Analysis Agent that computes metrics and generates PDF result documents.
  5. A Report Synthesizer Agent that produces executive intelligence summaries.

Most importantly, Mam, all agent interactions are governed by a Zero-Trust 
Security Gateway. No agent is ever allowed to execute a tool directly. Every tool 
call is intercepted, checked against a strict allowlist policy, and permanently 
recorded in an SQLite audit trail.

Let me walk you through the architecture and how these modules work together."

SECTION 2: HIGH-LEVEL ARCHITECTURE & 8-MODULE BREAKDOWN (3 Minutes)
================================================================================

[ACTION TO DO]:
Open the parent pom.xml file in your IDE to show the modular structure.

[FILE TO SHOW MAM]:
  d:\java_project\mci-system\pom.xml

[WHAT TO SAY TO MAM]:
"Mam, we built this project using a clean, decoupled multi-module Maven architecture. 
Each module has a single responsibility, ensuring maintainability, testability, 
and zero circular dependencies. Here are the 8 core modules:

1. mci-core:
   - Contains the core domain models and value objects: Task, SubTask, AgentType, 
     ToolRequest, ToolResponse, and Decision.
   - It has zero third-party dependencies, making it pure domain logic.

2. mci-gateway:
   - The security heart of the system.
   - Implements the 'Zero-Trust' paradigm using ToolGateway and PermissionPolicy.
   - Every file write, web request, or container execution must pass through here.

3. mci-tools:
   - The concrete tool implementations:
     * FileTool & FileWriterTool (sandboxed file I/O)
     * BrowserTool (HTTP client and HTML scraping via Jsoup)
     * DockerTool (sandboxed process/container execution with timeout control)
     * PdfTool (PDF generation using OpenPDF / iText)

4. mci-agents:
   - Contains specialized AI agents integrated with Google Gemini via LangChain4j.
   - Includes AgentDispatcher, NavigatorAgent, DockerAgent, DataFileAgent, and ReportAgent.
   - Includes an autonomous self-correction loop for code generation.

5. mci-orchestrator:
   - Contains the Planner (which asks Gemini to break goals into subtasks)
   - Contains the Scheduler (which executes the DAG sequentially, checking 
     upstream dependencies before running downstream tasks).

6. mci-persistence:
   - Pure JDBC-based persistence with an embedded SQLite database (mci.db).
   - Provides thread-safe DAOs for Runs, SubTasks, Artifacts, and Audit Logs.

7. mci-web:
   - Spring Boot 3.3.5 web application providing REST endpoints, Server-Sent Events 
     (SSE) for live telemetry, and an embedded modern web dashboard.

8. mci-app:
   - A standalone Command-Line Interface (CLI) version with colored ANSI logging, 
     allowing the whole system to be run without a web browser."

SECTION 3: STEP-BY-STEP FLOW & FILE EXECUTION ORDER (4 Minutes)
================================================================================

[WHAT TO SAY TO MAM]:
"Now Mam, let's trace the exact lifecycle of a mission—from the moment a user 
types an objective until the final PDF report is rendered on the web.

Here is the exact order of execution across the files:

--------------------------------------------------------------------------------
PHASE 1: MISSION SUBMISSION & ASYNCHRONOUS INITIALIZATION
--------------------------------------------------------------------------------
Step 1. User Enters Objective:
  - On the Web UI (index.html), the user types:
    'Research quantum computing trends, compute algorithm performance in Python, and produce an executive report.'
  - JavaScript sends an HTTP POST to: /api/runs.

Step 2. Controller & Thread Hand-off:
  - FILE: mci-web/src/main/java/com/mci/web/controller/RunController.java
    Method: createRun(@RequestBody CreateRunRequest request)
  - This immediately delegates to:
    FILE: mci-web/src/main/java/com/mci/web/service/RunExecutionService.java
    Method: startRun(String objective)
  - RunExecutionService creates a new run ID (e.g. 'run-16'), creates a workspace 
    directory (/workspace/run-16), saves the Task as RUNNING in SQLite via RunDao, 
    and hands off execution to an asynchronous background worker pool (ExecutorService).
  - The controller immediately returns HTTP 201 Created with the runId, keeping 
    the web UI fast and non-blocking.

Step 3. Real-Time SSE Subscription:
  - The frontend connects an EventSource to: /api/runs/run-16/stream.
  - RunExecutionService registers an SseEmitter for this client. Now any agent 
    status update, tool call, or file creation is instantly pushed to the browser.

--------------------------------------------------------------------------------
PHASE 2: AUTONOMOUS PLANNING & DAG DECOMPOSITION
--------------------------------------------------------------------------------
Step 4. Task Decomposition by Gemini AI:
  - FILE: mci-orchestrator/src/main/java/com/mci/orchestrator/Planner.java
    Method: plan(String runId, String objective)
  - The Planner calls Google Gemini (gemini-3.5-flash-lite via LangChain4j).
  - The LLM parses the English objective into 2-4 structured subtasks with designated 
    agent types:
      * Step 1: NAVIGATOR -> Browse web for quantum computing benchmarks -> sources.txt
      * Step 2: DOCKER -> Write and execute Python script in sandbox -> solution.py & docker_output.txt
      * Step 3: REPORT -> Synthesize all findings into executive markdown -> report.md
  - Each SubTask is inserted into SQLite via SubTaskDao with status PENDING.

--------------------------------------------------------------------------------
PHASE 3: DEPENDENCY-AWARE SCHEDULING
--------------------------------------------------------------------------------
Step 5. Sequential DAG Execution:
  - FILE: mci-orchestrator/src/main/java/com/mci/orchestrator/Scheduler.java
    Method: executeAll(List<SubTask> subtasks)
  - The Scheduler loops through each subtask in sequence.
  - First, it calls areDependenciesMet(): it verifies that the upstream subtask 
    is marked as DONE in SQLite. If an upstream task failed, downstream tasks are 
    marked as SKIPPED to prevent cascading errors.
  - If dependencies are satisfied, the Scheduler marks the subtask as RUNNING and 
    fires an onSubTaskStatusChanged event, which RunExecutionService pushes to the 
    web UI over SSE.

--------------------------------------------------------------------------------
PHASE 4: AGENT DISPATCHING & ZERO-TRUST GATEWAY INTERCEPTION
--------------------------------------------------------------------------------
Step 6. Routing to Specialized Agent:
  - FILE: mci-agents/src/main/java/com/mci/agents/AgentDispatcher.java
    Method: execute(SubTask subTask)
  - The Dispatcher uses a Java switch pattern to send the subtask to the correct 
    agent (NavigatorAgent, DockerAgent, DataFileAgent, or ReportAgent).

Step 7. Autonomous Execution & Tool Requests:
  - Let's look at DockerAgent:
    FILE: mci-agents/src/main/java/com/mci/agents/DockerAgent.java
    * It prompts Gemini to write a self-contained Python script (solution.py).
    * It creates a ToolRequest for tool 'file.write'.
    * Notice: The agent DOES NOT write to disk itself. It calls:
      ToolResponse resp = gateway.execute(toolRequest);

Step 8. Zero-Trust Security Gatekeeper:
  - FILE: mci-gateway/src/main/java/com/mci/gateway/ToolGateway.java
    Method: execute(ToolRequest request)
  - The ToolGateway halts the execution and checks:
    FILE: mci-gateway/src/main/java/com/mci/gateway/PermissionPolicy.java
    Method: check(AgentType agentType, String toolName)
  - It consults the strict Allowlist:
    * Is DOCKER allowed to use 'file.write'? -> YES (ALLOWED)
    * Is DOCKER allowed to use 'browser.fetch'? -> NO (DENIED)
  - ToolGateway logs the decision to the AUDIT table in SQLite BEFORE calling the tool.
  - ToolGateway then executes the tool (e.g. FileWriterTool writes solution.py to /workspace/run-16).
  - Next, DockerAgent requests tool 'docker.run'. Gateway validates it and runs 
    DockerTool, executing the code inside a container and saving stdout to docker_output.txt.

Step 9. Autonomous Fix-and-Retry Loop:
  - If the script fails with a syntax error or runtime exception, DockerAgent 
    captures the error traceback, feeds it back to Gemini, generates a corrected 
    script, and retries (up to 3 attempts) automatically!

--------------------------------------------------------------------------------
PHASE 5: SYNTHESIS & ON-WEB ARTIFACT DELIVERY
--------------------------------------------------------------------------------
Step 10. Executive Report Synthesis:
  - FILE: mci-agents/src/main/java/com/mci/agents/ReportAgent.java
  - The final step routes to ReportAgent. It reads all prior artifacts in the run 
    folder and asks Gemini to synthesize an Executive Intelligence Report (report.md).
  - DataFileAgent can also generate results.pdf using PdfTool.

Step 11. Completion & Dynamic Web Explorer:
  - When all subtasks reach DONE, RunExecutionService marks the run as DONE.
  - The scanAndEmitArtifacts() method discovers all generated files (report.md, 
    results.pdf, solution.py, docker_output.txt, sources.txt) and fires an SSE 
    'artifact_created' event to the frontend.
  - On the Web UI, interactive chips and file cards appear. The user can click 
    any file to open the built-in modal viewer (PDF viewer, Markdown rendered view, 
    or syntax-highlighted code viewer)."

SECTION 4: ZERO-TRUST SECURITY GATEWAY & AGENT SPECIALIZATION (3 Minutes)
================================================================================

[WHAT TO SAY TO MAM]:
"Mam, I want to emphasize the security architecture of our system, because this 
is what makes MCI enterprise-ready compared to standard open-source agent scripts.

In our system, we follow the principle of Least Privilege (Zero-Trust):

1. The Permission Allowlist Matrix:
   - NAVIGATOR Agent: Only allowed 'browser.fetch' and 'file.write'. Cannot execute code.
   - DOCKER Agent: Only allowed 'docker.run', 'file.read', and 'file.write'. Cannot touch the network.
   - REPORT Agent: Only allowed 'file.read' and 'file.write'. Cannot run shell commands.
   - DATA_FILE Agent: Only allowed 'file.read', 'file.write', and 'pdf.generate'.

2. Path Traversal Protection:
   - In FileTool and FileWriterTool, every file path is sanitized. If an agent 
     attempts to use '../' to escape its allocated /workspace/run-X directory, 
     the gateway immediately rejects the request.

3. Sandbox Isolation:
   - DockerTool runs scripts with timeouts and memory constraints. Even if an agent 
     generates an infinite loop like 'while True: pass', the process is killed 
     after 30 seconds.

4. Immutable Audit Trail:
   - Every single decision (ALLOW or DENY), argument payload, timestamp, and result 
     is written to the SQLite audit log table. If someone asks: 'What did the AI do?', 
     we have full forensic traceability."

SECTION 7: TOP 10 ANTICIPATED TEACHER QUESTIONS & WINNING VIVA ANSWERS
================================================================================

Q1: "Why did you build this in Java instead of Python, which is more common for AI?"
A1: "Python is great for quick scripts and data science, but in an enterprise 
multi-agent system, Java provides:
  1. Strong typing and compile-time safety across agent contracts.
  2. Enterprise multi-threading with robust ExecutorService thread pools.
  3. Spring Boot's battle-tested REST and SSE infrastructure.
  4. Better zero-trust sandboxing and permission policy enforcement.
We use Python where it excels—inside our Docker sandboxed execution container—while 
Java orchestrates the entire intelligence lifecycle."

Q2: "What prevents an agent from hallucinating or running 'rm -rf /'?"
A2: "Two layers of defense:
  1. The Zero-Trust ToolGateway: Agents cannot execute arbitrary commands; they 
     must request 'docker.run' or 'file.write'. PermissionPolicy blocks unauthorized tools.
  2. Workspace Sandboxing: Paths are strictly resolved relative to the specific 
     run directory. Any relative path traversal (like ../..) throws a SecurityException."

Q3: "How does the system handle dependencies between agent tasks?"
A3: "In Scheduler.java, tasks are represented as a Directed Acyclic Graph (DAG). 
Before any subtask executes, areDependenciesMet() queries SQLite to confirm all 
upstream prerequisite tasks have reached TaskStatus.DONE. If a prerequisite failed, 
the downstream task is automatically marked SKIPPED."

Q4: "How does the frontend receive live updates without polling?"
A4: "We use Server-Sent Events (SSE) via Spring Boot's SseEmitter. When the user 
opens a mission, the browser connects to /api/runs/{id}/stream. As agents transition 
states or make gateway tool calls, the backend pushes JSON events over a persistent 
HTTP connection, eliminating expensive HTTP polling."

Q5: "How does Docker execution work if Docker is not installed on the machine?"
A5: "DockerTool is designed with graceful fallback. It first attempts to run via the 
local Docker daemon using an isolated container. If Docker is unavailable in the host 
environment, it falls back to a sandboxed local ProcessBuilder with strict timeout 
enforcement (30 seconds), capturing standard output and error streams."

Q6: "Where is the database stored, and why did you choose SQLite?"
A6: "We use an embedded SQLite database stored at mci-system/data/mci.db. SQLite is 
serverless, lightweight, ACID-compliant, and runs in-process with zero setup overhead. 
We wrote our schema in schema.sql with clean relational tables: runs, subtasks, 
artifacts, and audit_log."

Q7: "Which LLM model are you using, and how do you handle rate limits?"
A7: "We connect to Google Gemini AI via the LangChain4j framework using the 
gemini-3.5-flash-lite model. In LlmFactory.java, we implemented an exponential 
backoff retry wrapper (generateWithRetry) that handles transient 429 rate limits or 
network hiccups automatically."

Q8: "What are the output artifacts produced by a run?"
A8: "Depending on the objective, the agents produce:
  - sources.txt: Raw research and reference URLs extracted by NavigatorAgent.
  - solution.py: Clean Python code authored by DockerAgent.
  - docker_output.txt: Execution output and benchmark logs from the sandbox.
  - results.pdf: Visual multi-page PDF document generated by DataFileAgent.
  - report.md: Executive Markdown report synthesized by ReportAgent.
All files are viewable directly on the web interface."

Q9: "Can you explain what happens if Gemini writes Python code with a syntax error?"
A9: "In DockerAgent.java, we have an autonomous self-correction loop. We run the code 
inside the container. If the exit code is non-zero, the stderr traceback is captured. 
The agent feeds both the failing code and the traceback back to Gemini with a 
correction prompt. It fixes and reruns the script automatically up to 3 times."

Q10: "How did you ensure that files can be viewed on the web without downloading?"
A10: "In RunController.java, we built a dedicated /api/runs/{id}/artifacts/{file}/view 
endpoint that serves files with the HTTP header:
'Content-Disposition: inline; filename=...' instead of 'attachment'.
Along with the correct MIME type (such as application/pdf or text/markdown), this 
instructs the browser to render the file natively inside an embedded iframe or modal."
